# Research Roadmap 2026–2027

**Syn Research Laboratory / Synapse Core Infrastructure**
Status: active · Horizon: 9 months · Last updated: 2026-10-19

---

## Scope and epistemic status

This roadmap covers **computational (dry-lab) work only**. Every deliverable below is a
simulation, a statistical pipeline, or a set of numerical criteria. None of it constitutes
experimental validation, and none of it is a therapeutic claim.

Where this repository publishes numbers produced by models, those numbers are labelled as
model output. See
[`papers/deeptech-proofs-04-epigenetic-anchor/`](../papers/deeptech-proofs-04-epigenetic-anchor/)
for the hypothesis that motivates Milestone 1; its predicted magnitudes are unvalidated and
are part of what this roadmap sets out to test computationally.

**Infrastructure.** All work runs on self-hosted compute (local GPU and a commodity VPS),
with no institutional overhead. Reproducibility is a hard requirement: every milestone ships
a command that a reviewer can run.

## Milestone 1 (months 1–3) — Allosteric pocket characterisation and ligand docking

**Module:** [`core/sirt6_resonance/`](../core/sirt6_resonance/)

SIRT6 is an NAD⁺-dependent deacetylase with experimentally characterised allosteric
activation. Published co-crystal structures provide the starting geometry:

| PDB | Contents |
|-----|----------|
| [5Y2F](https://www.rcsb.org/structure/5Y2F) | Human SIRT6 in complex with allosteric activator MDL-801 |
| [5MF6](https://www.rcsb.org/structure/5MF6) | Human SIRT6 in complex with activator UBCS039 |
| [3K35](https://www.rcsb.org/structure/3K35) | Human SIRT6, reference structure |
| [5X16](https://www.rcsb.org/structure/5X16) | SIRT6 apo structure |

### Deliverables

1. **D1.1 — Reproducible docking harness.** Ligand docking into the characterised allosteric
   pocket across the structures above, driven by a pinned configuration file. Known activators
   are re-docked first as positive controls; the harness is only considered working if it
   recovers the crystallographic pose within an agreed RMSD threshold.
2. **D1.2 — Pocket geometry and energetics report.** Pocket volume, residue contacts, and
   scoring-function output per structure, with the scoring function's known error bars stated.
3. **D1.3 — Exploratory normal-mode analysis.** Low-frequency vibrational modes of the pocket
   region, reported as a structural observable.

### Acceptance criteria

- Re-docking of MDL-801 into 5Y2F and UBCS039 into 5MF6 reproduces the crystallographic pose
  within the RMSD threshold recorded in `core/sirt6_resonance/config/docking.yaml`.
- The full run is reproducible from a single command on a clean checkout, given the external
  docking binary.
- Every reported score carries the scoring function's published uncertainty.

### Limitations (stated up front)

- Docking scores are **ranking heuristics, not binding free energies**. Agreement with
  experiment is routinely poor in absolute terms.
- The normal-mode analysis is **exploratory**. There is no established causal link between
  computed vibrational modes of a protein pocket and catalytic activation of SIRT6, and this
  milestone does not attempt to establish one. Any observed correspondence is a hypothesis
  that would require spectroscopic and enzymatic experiments to test.
- Nothing in this milestone demonstrates activation of SIRT6 by any non-chemical means.

## Milestone 2 (months 4–6) — Epigenetic clock calibration and ChIP-seq triage

**Modules:** [`models/dunedin_pace/`](../models/dunedin_pace/),
[`models/chipseq_triage/`](../models/chipseq_triage/)

This milestone is split by data type, because the two halves carry different licensing and
different failure modes.

### D2.1 — Methylation clock calibration (`models/dunedin_pace/`)

Calibration and drift characterisation of the DunedinPACE clock
(Belsky et al. 2022, *eLife* 11:e73420) on **public** methylation array data (450K/EPIC)
retrieved from GEO.

The reference implementation (`danbelsky/DunedinPACE`) is **GPL-3.0**. This repository does
not vendor, import, or link that code. It is invoked as an external process across a
command-line boundary, and the harness in this directory is Apache-2.0. See
[`models/dunedin_pace/README.md`](../models/dunedin_pace/README.md).

### D2.2 — ChIP-seq QC and triage (`models/chipseq_triage/`)

Quality control and triage for H3K9ac and H3K56ac ChIP-seq datasets — both are reported
SIRT6 deacetylation substrates — over public accessions: alignment quality filtering, peak
calling with FDR control, and replicate concordance.

### D2.3 — Association analysis

Association between differential histone occupancy at SIRT6 target loci and clock scores,
reported with confidence intervals, sample size, and multiple-testing correction.

### Acceptance criteria

- Clock scores reproduce the reference implementation's output on a shared public dataset
  within a documented numerical tolerance.
- Every accession used is public and listed in the module configuration.
- Association results report effect size with confidence intervals, not a bare correlation
  coefficient, and state the number of independent samples.

### Limitations

- Correlation between a histone mark and a clock score is **not evidence of a causal
  relationship**, in either direction.
- Epigenetic clocks are statistical predictors trained on specific cohorts. Scores do not
  transfer automatically across tissue types, platforms, or populations, and a change in
  score is not by itself a change in health.
- This milestone analyses existing public data. It generates no new biological measurements.

## Milestone 3 (months 7–9) — In-silico boundary constraints and dedifferentiation screening criteria

**Module:** [`safety/paleo_shield/`](../safety/paleo_shield/)

Partial reprogramming approaches carry a documented risk of loss of cell identity. This
milestone formalises **numerical screening criteria** that flag, in simulation and in
published expression data, trajectories that drift toward a dedifferentiated state.

### Deliverables

1. **D3.1 — Constraint set.** Explicit, documented numerical bounds (lineage-identity score,
   pluripotency-marker expression bounds, trajectory-divergence limits), each with its source
   and its assumptions written down.
2. **D3.2 — Triage harness.** Code that evaluates a trajectory or an expression profile
   against the constraint set and returns a structured flag with the reason.
3. **D3.3 — Open benchmark.** A public benchmark suite with labelled positive and negative
   cases, so that others can measure the criteria's false-negative rate rather than take it
   on trust.

### Acceptance criteria

- Every constraint cites the published source of its threshold.
- The benchmark reports **false-negative rate explicitly**; a screening criterion that never
  misses in its own benchmark is reported as untested, not as perfect.
- The harness runs on public data from a single command.

### Limitations — read this before citing the module

**This module does not verify safety, and must not be described as doing so.** It computes
numerical criteria over simulated or published data. It cannot establish that any
intervention is safe, non-oncogenic, or fit for use in any organism.

Assessment of oncogenic risk requires, at minimum: cell-based assays including soft-agar and
karyotype analysis, long-term in-vivo tumour-incidence studies in appropriate animal models,
and subsequent regulated clinical investigation. None of these are in scope here, and no
output of this module substitutes for any of them.

The name "Paleo-Shield" is a project codename for a computational module. It is not a claim
of protection.
